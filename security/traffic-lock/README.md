# 项目流量锁

默认状态：关闭。此代码是受保护的HTTP入口，不是首页开关。现有业务代码和UI未重写。

**线上状态：尚未部署、尚未核验。把这些文件上传GitHub不等于已有网站被锁。**
现有公开端口、默认托管域名、预览域名、云函数、数据库/对象存储直连和CDN缓存必须逐个收口。

## 锁的规则

- 新状态库默认关闭；没有有效的管理端开放操作，HTTP页面/资源/API/Webhook都返回403，不触达业务服务。
- 仅具有服务器操作系统权限的管理端可以运行open。没有远程开放接口，网页、客户端和访问请求不能自行开放。
- 开放1至1440分钟，超时关闭；close立即停止后续请求和响应分块。已经发送的字节无法收回，已经进入业务服务的事务不由网络锁撤销。
- 同一来源60秒超过120次请求：封禁来源。
- 同一来源、方法和规范化路径10秒超过20次请求：封禁来源；变化查询参数/部分编码不能重置计数。
- 单项目60秒超过600次请求、或转发字节超过50MiB：关闭项目。
- 来源封禁和项目熔断保存在独立SQLite状态库，重启或等待不自动解锁。项目再次open不会解除来源封禁，unblock必须另行明确执行。
- 普通刷新和加载不同资源允许；第二次正常访问不会被切断。阈值是初始配置，不是假定已经测得的业务基线。
- 数据库错误、缺失环境配置和授权服务故障时拒绝访问。
- 固定来源，不从访问者指定URL选择目标；未信任代理的X-Forwarded-For/X-Real-IP被忽略；IP以持久随机盐HMAC保存，不保存访问令牌或请求查询参数。

## 管理命令

Python 3.11+，无第三方依赖。替换下面PROJECT为本仓库名称；STATE必须是服务器上的持久私有路径，不是仓库文件。

```bash
python3 gate.py --project PROJECT --state STATE status
python3 gate.py --project PROJECT --state STATE open --minutes 60 --reason '所有者确认开放预览' --confirm-owner
python3 gate.py --project PROJECT --state STATE close --reason '所有者要求关闭'
python3 gate.py --project PROJECT --state STATE unblock --ip 192.0.2.1 --reason '所有者核实正常来源' --confirm-owner
```

管理权限依赖服务器账户/SSH权限及状态目录0700、文件0600。`--confirm-owner`记录显式意图，不是身份认证。不能把这些命令交给公开CI触发器、应用账号或未经授权的人员。凭据、状态库、日志和证书绝不提交Git。

## 独立HTTP入口

业务程序只监听本机/私有网络，禁止公网直接访问；锁是唯一可达入口。

```bash
python3 gate.py --project PROJECT --state STATE serve --upstream http://127.0.0.1:4310 --bind 127.0.0.1 --port 8443
```

绑定公网时必须提供GATE_TLS_CERT和GATE_TLS_KEY（受保护证书文件路径），否则拒绝启动。TLS最低1.2；HTTP处理并发上限32、单次套接字读超时10秒、响应转发循环最长60秒（上游单次阻塞读还可能占用最多10秒）、请求体上限8MiB。不转发WebSocket升级、CONNECT或分块请求；需要长连接的项目需在平台防火墙/网关层完成对应专用策略，不能宣称该HTTP适配已覆盖它们。

TLS反向代理必须先经此锁再到业务服务。只有明确设置GATE_TRUSTED_PROXIES中的可信代理CIDR，才接受该代理覆写的X-Real-IP。代理必须删除用户给的X-Real-IP并重新设置；不要信任整个公网或任意私有地址。否则所有代理流量会按代理IP计数并可能共同被封。

状态库位于单台权威服务的持久磁盘；不同副本不得各用自己的SQLite，否则计数与关闭状态分裂。多区域/大规模生产应迁移到原子共享存储或托管WAF，不能把这个实例称为已具备DDoS容量。

## Netlify前置入口

适用于本仓库已存在netlify.toml的项目。新增edge函数匹配全部路径，没有设置以下服务器环境变量时默认拒绝：

- TRAFFIC_LOCK_PROJECT：本仓库名称。
- TRAFFIC_LOCK_AUTHORIZER_URL：固定HTTPS地址，路径必须/_traffic_lock/authorize。
- TRAFFIC_LOCK_AUTHORIZER_KEY：32字节以上随机服务间秘密，仅服务器使用。
- 授权服务对应GATE_AUTHORIZATION_KEY，值相同；其状态库也默认关闭。

密钥本轮未生成、未写入仓库。授权地址不能指向被该edge函数保护的同一个网站，否则形成递归；应使用独立私有受控服务。管理命令仍在该服务的可信服务器账户下执行。

edge使用平台context.ip，授权判断不缓存，失败不放行；仅路径/方法/IP发送给授权服务，不发送cookies、会话或业务正文。
Netlify路径适配仅计数请求，**不能测量所有下游字节**；带宽熔断须让响应经过HTTP锁或配置托管平台WAF/预算控制。本轮未核验平台对直接函数、后台函数、默认域名/预览域名的实际覆盖；上线后必须检查，而不是默认认为它们被保护。

## 项目边界和完整生效要求

1. 锁部署并默认拒绝；业务原始端口/默认托管域名不允许绕过。
2. 独立API、静态资源、Webhook、原始云函数路径、预览地址逐个验证；私有健康检查不应成为公开豁免。
3. 浏览器直连数据库/存储不能靠网页锁拦截。需在相应平台撤销公开访问或增加独立服务端授权边界；本轮没有修改数据库策略。
4. 清除部署前的公开CDN缓存，并验证关闭后不再返回已缓存内容。
5. 先确认公开请求全被拒绝，再由所有者限时开放；触发重复请求/异常后复核封禁及管理恢复。

默认限制外部访问，不禁止应用主动访问第三方API、后台定时任务，也不控制GitHub源码仓库访问。扩展/纯源码/档案仓库没有HTTP服务器的，不虚构一个已经存在的公网入口；package仅供将来部署时使用，manifest记录当前类型。

## 检查

```bash
python3 -m unittest discover -s . -p test_gate.py -v
```

覆盖默认关闭、过期、重启、重复请求、来源伪造、并发计数、项目隔离、请求/带宽熔断和真实本地HTTP请求不触达来源。本地使用合成来源；未调用真实客户、消息或支付服务。测试通过不等于线上部署完成。
